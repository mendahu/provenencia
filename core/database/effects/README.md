# effects

What a change to one table touches after the row is written: the Evidence graphs whose loaded rows it moves, the keyed partial reads it moves per graph, the handles whose reconciled values must be rewritten, the search documents to reproject, and whether vocabulary labels or structure changed.

One `Effect` per table outside [`catalogmodel`](../catalogmodel)'s skip bucket. An empty field means that job is unaffected. `None` is an explicit empty entry (`users`, layout rows, grade tables).

Paths walk edges declared in `catalogmodel.FKs`: `up`, `across`, `inbound`, `from`, `field`, `self`, `chain`, `union`, `onField`, `onStatus`, `onDelete`, and `sql` for a walk those cannot say. Package init panics when a path names a missing edge. A column on the diff contributes its old and new ids. A column absent from the diff is read from the live row. A delete's old fields are used only when the row is already gone.

`Handles` and `Resolve` take `[]rowchange.Change`. `Resolve` is the one walk of a batch: it returns `Set.SourceScopes` and `Set.HandleScopes` (the audit scopes), `Set.Deleted` (the ids a change deleted, by entity: `Effect.Deleted` is a path guarded by `onDelete` that ends at the entry's own table, reported under its `Entity`, so `canonical_entity` lists the handles and a merge, which updates a handle, is not listed; the app reads it from `WriteEffects.deleted`), `Set.EvidenceGraphs` (the Evidence graphs whose loaded rows a change moves: graphcache drops each, and nothing else follows it), `Set.Reads` (the keyed partial reads a change moves, each with the Evidence graphs it moved them for), `Set.Handles` (the recompute set), search documents, `Set.Lists` and the structure flag.

A write names only the graphs whose loaded rows it moves. A Subject, Observation or claim row names its Subject's graph. A Citation names the graphs of its Observations (`EvidenceGraph`), and so a Citation with none yet names no graph for the cache, while its `citations` read is the graph it was made in (`graph_id`); an Artifact's own fields move no loaded row, so an Artifact row names none (its Citations and Observations carry their own). A Source row names every graph of the Source only on a write that changes `title` (`onField`), because a graph's search document and canvas hold the Source title; the same write reprojects those graphs' search documents (`DocEvidenceGraph`). Graph rows (`evidence_graphs`) name themselves; link rows (`evidence_graph_artifacts`) name no graph, since a cached graph holds no links.

`Set.Reads` is the shape of `Set.Search`: `Effect.Reads` is a list of `ReadPath{Read, Path}` where the path ends at the read's key table (`Read.KeyTable()`: Evidence graphs for `citations` and `evidence_graph_progress`, Sources for `evidence_graphs`, Properties for `property_terms`), and `Resolve` collects the ids per `Read`, in the order of `effects.Reads`. The reads are a closed vocabulary like `Lists`: `citations` (a graph's citation counts and citations by Artifact; moved by Citations, by their `graph_id`, Observations, and the value rows an Observation owns; a link row holds no Citation and moves none) `evidence_graph_progress` (a graph's Subject, filed and Observation counts; moved only by Subjects, Observations, Identity Claims and their evidence, so an Artifact edit or a Source title edit never refetches progress) and `property_terms` (a Property's term list; moved by its terms, so a term write reloads only that Property's list). A new keyed read is a `Read` constant, a `KeyTable` case, an entry in `Reads` and `Reads:` on the registry entries that move it; the wire key is the constant's value (`WriteEffects.reads`) and Swift's `CatalogRead` mirrors it, with a `refresh` entry on the descriptors that cache it.

`Set.Lists` holds the catalog-wide lists the batch changed, each once, in the order of `effects.Lists` (`Set.Has(l)` tests one): `source_vocabulary` (a Source type or a metadata field changed), `property_vocabulary` (a subject type, Property, Property term or binding changed), `property_usage` (an Observation was created, deleted, or moved to another Property: `Effect.ListsOnField` narrows an update to the ones that write `property_id`) and `counts` (a Source or a handle of any type was created, deleted or merged, so a sidebar count may have changed: `sources` sets `Effect.ListsOnCreateDelete`, so an update never moves it, and `canonical_entities` narrows an update to a write of `merged_into_id`). Which updates move `Lists` is one choice per entry: all, those writing `ListsOnField`, or none (`ListsOnCreateDelete`). A new catalog-wide list is a `List` constant, an entry in `Lists` and `Lists:` on the registry entries that move it; the wire key is the constant's value (`WriteEffects.lists`) and Swift's `CatalogList` mirrors it. `Effect.HandleScope` is the handles whose last activity a change moves; `Handles` is wider. `Effect.SourceScope` is the Source whose last activity a change moves, and `Effect.EvidenceGraph` is the Evidence graph whose loaded rows changed (a path that ends at `evidence_graphs`), so a note, metadata, credibility, or file write moves activity and drops no cached Evidence graph. [`writes.Run`](../../writes) calls `Resolve` once, hands the `Set` to `audit.Record`, then recomputes handles and reprojects search when those sets are non-empty. Each scope path is walked once per write. `Run` sets `Set.SummaryDeps` from the [input index](../../../docs/deployment-plan/archive/spike-14/summary-inputs.md) (`searchindex.ReprojectChanged`).

`Scopes` (`scopes.go`) declares every audit scope type once: its name and which ids of a `Set` belong to it (`source` from `SourceScopes`, `canonical_entity` from `HandleScopes`). `audit.Record` stores one `audit_transaction_scopes` row per id of each `Scopes` entry, and the display cache ([`graphcache`](../graphcache)) keeps each type's last activity current from the same ids. A new scope type is one `Scopes` entry. `Commit` (`commit.go`) is a landed write: its revision, the time that revision was recorded, and its `Set`. It lives here because the display cache accepts it and `core/database`, which imports the cache, hands it to listeners. This package does not import `audit` or [`deleteimpact`](../deleteimpact).

`registry_completeness_test.go` checks that every non-skip table has an entry and that a cascade into a table with effects is audited. `handle_paths_test.go` checks membership, trigger columns, claim status, and date values. Source parity runs beside `audit.TestSourceScopes`.

The map of the schema packages is in [`catalogmodel`](../catalogmodel/README.md).

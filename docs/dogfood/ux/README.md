# Dogfood UX entries

One file per finding: `YYYY-MM-DD-<slug>.md`. Not a commitment and not a test plan. Feedback from people using the app only: no PR follow-ups, review findings or plan Out lines.

When a note is pulled into a spike or parked as an idea, delete it here. The plan or idea is the copy.

## How to add

```markdown
# Short title

- **Date:** YYYY-MM-DD
- **Type:** Bug / Friction / Idea
- **Where:** Evidence graph / citation composer / Sources list / …
- **Annoyance:** What you were doing and what felt wrong.
- **Wanted:** (optional) What would have been better.
```

Code notes are fine when they help the next reader; keep them under a `## Code notes` heading.

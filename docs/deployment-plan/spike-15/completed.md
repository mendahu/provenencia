# Spike 15 — Completed

One short paragraph per landed PR, newest first. PR map: [`deployment-plan.md`](deployment-plan.md).

**S15-26 — The metadata board takes an owner** ([#798](https://github.com/mendahu/provenencia/pull/798)). The Source page's Metadata board is now one board model and view (`MetadataBoardModel`, `MetadataBoardView`) over a host that holds an owner's rows and runs its writes (`MetadataBoardHost`; `SourcePageMetadataHost` for the Source), and the page's one Add dialog and clear confirm (`MetadataBoardDialogs`) target whichever board asked, so S15-09 – S15-11 instance the same board. The Swift store's four metadata writes take a `MetadataOwner` (level, id), and Set and Clear answer the owner's whole row set like dismiss and reorder (`SetMetadataResponse.metadata`, `ClearMetadataResponse.metadata`), so Swift no longer copies the engine's row placement or Clear rule. `.mutatedSourceMetadata` is gone: every board write applies `.mutatedSourceWorkspace`, which reached the same key. The Source page looks and behaves as before. Product 0.10.3.

**S15-08 — Artifacts and graphs hold metadata** ([#791](https://github.com/mendahu/provenencia/pull/791)). An Artifact (the copy used) and an Evidence graph (the item cited) now hold metadata values and a layout with the same fields, rules and audit as a Source, in four new tables (migration `000065`) that every `sourcemetadata` function reaches through its store table, and that scope the owner's Source. Their metadata is released, audited, with the Artifact, graph or field; a Source delete now audits each graph's metadata through the one graph removal (`deleteimpact.ReleaseGraph`), and a deleted parent's change resolves the Source for the rows released with it. A field in use on any of the three levels cannot be deleted, and Used by on fields, Source types and Properties comes from one delete-impact total read in one batch per list (a Property now counts its terms too); the field list reloads when any value is held or released, through the `metadata_field_usage` list. Copy Source carries each chosen Artifact's own metadata whatever the Metadata tick says. Over FFI the four Source board RPCs became owner RPCs (`Set/Clear/DismissSuggestion/ReorderMetadata`), with `GetMetadataBoard`, `metadata` drafts saved with `CreateArtifact`, `CreateEvidenceGraph` and `UpdateEvidenceGraph`, and one board per Artifact on `GetSourceWorkspace`; the Swift store keeps its Source methods until S15-26. No board is drawn yet. Three strings name the new holders, and the Property inspector's count label, the field in-use notice and the Copy Source Metadata hint say what they count. Product 0.10.0.

**S15-07 — Metadata operations take an owner** ([#787](https://github.com/mendahu/provenencia/pull/787)). Nothing changes on the Source page or in Copy Source. Inside, every `sourcemetadata` function now takes an owner (a level and an id) and only the Source level is wired, so Artifacts and graphs add two table entries later. The package gains `ListByOwnersTx`, one read of many owners' values per level for the citation resolver, and `Apply`, which saves a draft of values and layout by comparing it with what is stored; `CreateAll` is its empty-owner case, and `ListWorkspace` now reads in one read transaction with one field read. `ReadDraftTx` replaces the three single-Source reads, and a Copy Source draft carries one `sourcemetadata.Draft`. A dismiss or reorder that creates a layout row now audits `source_id` and `field_id` as new, as Copy Source's creates did. Every by-id `IN` read the PR adds goes through `sqlbatch`, so a list of any length stays under SQLite's bind limit. No version bump.

**S15-06 — Type suggestions have a level** ([#782](https://github.com/mendahu/provenencia/pull/782)). A Source type's suggested fields now carry a level (`source`, `artifact` or `graph`), and every existing suggestion became a `source` one, so the Source page and the Source types page show what they showed. One `vocabkey.Level` type (those three plus `citation`, which only built-ins will use) is mirrored by a Swift `Level` enum under two parity rows. Migration `000064` rebuilds `source_type_metadata_fields` with `level` in its key; `sourcevocab`'s suggestion functions and the seed registry take a level, the field count lives once in `sourcetypes.SuggestedFields` (source rows), and the three suggestion RPCs take a `level`, with the assign and remove replies carrying the engine's count that the type page now shows. Product 0.9.0.

**S15-32 — Copy Source can carry the date** ([#778](https://github.com/mendahu/provenencia/pull/778)). The Copy Source form has a fourth tick, Published date, whose hint is the date as the Sources list writes it ("4 Jul 1881", or the phrase); it starts ticked when the original is dated, and reads "None on this Source", unticked and disabled, when it is not. Ticked, the copy opens dated the same, with a `date_values` row of its own, so changing one Source's date later never touches the other; the not-public flag is still never carried. The Description, Metadata and Credibility ticks now share one `partTick` helper. `CopySourceRequest` gains `copy_date`, and `sourcecopy` reads the original's date into its draft and writes it with `sources.SetDate` in the one `copy_source` revision. Product 0.8.0.

**S15-04 — The Sources list shows and sorts by the date** ([#774](https://github.com/mendahu/provenencia/pull/774)). Each Sources list row shows its Source's published date: "Published 1 Jun 1880" under the type, "No published date" when undated, its own Published column at Wide (an undated Source reads "Undated"), and a type · Published record line under the title when the list is narrow. Two new sorts, "Published date, oldest first" and "newest first", order by Go's `date_sort_key` (`CatalogSource.dateSortKey`) with undated and phrase-only Sources last, by title; the choice is saved with the other list settings. At Wide the list centers at `PVSpacing.widthListWideMax` (1600 of content) with a hairline down each side (`pvListBand`), and Promote's list reads the same token. The Source page's date copy now says "Published" too. The graph column's hairline runs down the whole row when a title wraps. Product 0.7.0.

**S15-03 — The Source page shows the date and the Private switch** ([#766](https://github.com/mendahu/provenencia/pull/766)). On the Source page a researcher adds, changes and clears the Source's own date from its header, in a dialog with the shared date form, a "Reads as" line and Clear date, and marks the Source Private with a switch that saves at once. A missing Source is `sources.not_found` from every Source reader and writer, so a write to (or a visit of) a Source deleted in another window says "was deleted" and returns to the Sources list. The page moved onto Page columns: Metadata sits in a side column at Wide (`PVPageColumns(fillSplitSideMax:)`, `SourcePageOverviewLayout`). `PVSwitch` now speaks the toggle trait and its On or Off value. Product 0.6.0.

**S15-02 — Sources carry a date and a not-public flag** ([#762](https://github.com/mendahu/provenencia/pull/762)). A Source has an optional date of its own (a shared DateValue, set, edited in place and cleared by `SetSourceDate`, released when the Source is deleted) and a not-public flag that defaults to public (`SetSourcePublic`, stored and read back only). Every Source on the wire carries the date, a `date_sort_key` and `is_public`. The date order moved to `valuecompare.DateKeyOf`, which the Timeline, birth order, the Sources key and the reconciler's stored date `sort_key` now share (`CacheVersion` 24). `datevalues.PutTx`, `namevalues.PutTx` and `deleteimpact.ReleaseReplaced` are the one way an owner stores and releases a value row. No Swift view changes; product 0.5.0.

**S15-01 — The credibility argument is a text area** ([#758](https://github.com/mendahu/provenencia/pull/758)). The Source page's credibility argument is a multi-line text area that wraps and grows to 12 lines; Return adds a line and Save saves it with its line breaks. `PVTextArea` takes its own accessibility label. Two text areas in one column no longer crash: each finds its own text view and a text view keeps one Tab router.

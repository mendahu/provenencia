## S13-27 — Person record links read

**Landed 2026-11-07** in [#743](https://github.com/mendahu/provenencia/pull/743). The read behind how a person's records connect, with no view yet (S13-28 draws it). `GetPersonRecordLinks` (method 116) returns a Person's Evidence graphs, in the Sources section's order, and for each pair of graphs one line for each other person both name: the person's entity and a weak or strong weight, computed on each read and never stored. `recordlinks.Pairs` counts every pair through a shared index of who is in which graph, with one read-wide bound, `recordlinks.MaxReadWork` (1,100,000: 20 times the 53,900 work of a person in 50 household graphs); both it and `MaxPairWork` (45,000) count every link and property each member holds per member pair, so a crafted person with links to entities the other graph lacks cannot hang a read; the one-pair count is unexported. `persondetail.RecordLinks` loads each graph's layer from the shared Evidence layer and the catalog's value rules, and `persondetail` joins the matching guard's readers. The Swift store reads it into `CatalogPersonRecordLinks`, and the `.personRecordLinks` key reloads only when a write names its own handle or a graph it holds. The per-person keys now share two descriptor builders (`personSection`, `personGraphsSection`). A 50-graph read (1,225 pairs, three lines each) runs in about 50 ms cold and 40 ms repeat; the test helpers for timing moved to `databasetest`.

## S13-04 — Person family read

**Landed 2026-11-01** in [#671](https://github.com/mendahu/provenencia/pull/671). The engine answers who a person's family is: `GetPersonFamily` returns family units for a canonical person, each relative a `PersonSummary` with the link that says why they are there (recorded or implied, with its associations and shapes). Units come in a fixed order: each set of parents with the siblings through them, each partner with the children the two share (a co-parent who is not a spouse is a partner with no link), the children with no other known parent, and the siblings whose parents are not shown. The rules are `kinship.KinOf` and `kinship.FamilyUnits`, page-only like siblings; `persondetail.Families` loads and filters to canonical relatives for a list of ids in a fixed number of batches (`canonlinks.Reader.LoadRelationships`, which shares one walk, `loadSteps`, with `LoadSiblings`), and a warm read issues no graph query. The Swift side has the store method, a `FakeStore` seed and the `.personFamily` cache key, which any touched handle revalidates. No view reads it until S13-12.

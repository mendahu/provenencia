Frame 11 Slot contract What every row must fill, and what it may leave empty
Leading visual Required. 40px tile, hairline, sunken fill. Scan thumbnail → file-type glyph → kind icon, in that order of preference. The slot never collapses. Primary title Required. Body size, semibold, one line, ellipsis. Kind chip Required. 10px caps, hairline outline, muted — a label, not a badge. Never coloured by evidence grade. Secondary Required where the kind has identity beyond its name (type label, parent source, key · data type). Muted body-sm. Reference Optional. Mono micro, trailing, faint — accent only on an exact-ref match. Vocabulary rows leave it empty. Match context Optional. Mono label + italic excerpt, one line. Present only when the query did not appear in the title or ref.
Frame 12 Kinds the skeleton still has to hold Not in Spike 3 — drawn to prove the slots stretch
The row is the whole design; it should land in the system as OmnibarHitRow (Swift PVOmnibarHitRow), taking lead / title / kind / secondary / ref / context and a selected flag — nothing kind-aware inside it. The leading tile is Thumbnail extended with a glyph mode; the dropdown surface is the history-menu surface with a wider minimum. No other new primitives.
Held back deliberately Relationships get no row: their identity is two other records, so a one-line title would always be a sentence. Notes, metadata values and filenames under a source are not hits either — they roll up into the source row's match-context line, which is what stops the list filling with four rows pointing at the same record. Recent searches are not shown on an empty query: an empty project-scoped palette that lists nothing is honest, and a recents list would be read as results.
